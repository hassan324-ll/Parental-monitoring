# Database foundation
users (Laravel hashed passwords; nullable unique firebase_uid), families(owner_id → users), family_members(family_id,user_id,role), children(family_id), devices(family_id,child_id,public_id), device_pairings(family_id,token_hash,expires_at,consumed_at), permission_grants(device_id,permission,granted_at,revoked_at), app_usage_daily(device_id,day,package_name,duration_seconds), location_updates(device_id,coordinates,accuracy,recorded_at), screen_share_sessions(family_id,device_id,requested_by,status,expiry), alerts(family_id,type,payload,read_at), audit_logs(family_id,actor_id,action,subject_id).

Composite child/family and device/family foreign keys prevent mismatched ownership. Cascade family data deletion; restricted user deletes require an ownership transfer or explicit family deletion. Audit actors become null when deleted. Role enum owner/parent/viewer and unique memberships constrain duplicates. Pairing tokens store SHA-256 hashes of cryptographically random high-entropy tokens, never plaintext. Expiry and atomic single consumption still need service implementation.

Indexes: leading family_id indexes on children/devices for scoped pagination and counts; unique device public ID, unique family membership, device/day/package usage, device/time location, pairing expiry, family/time audit. Production constraints on coordinate ranges, maximum daily usage, consent ownership and lifecycle transitions are a next-phase requirement. Do not expose ingestion before those validations exist. No real seed data is created.
