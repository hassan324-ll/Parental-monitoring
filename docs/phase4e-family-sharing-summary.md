# Phase 4E — authorized saved-data summaries

GET `/api/v1/families/{family}/devices/{device}/sharing-summary` adds a bounded read-only contract for future parent presentation. It uses existing verified Firebase-parent authentication and parent throttling. FamilyAccess reloads current family visibility and permits only the family owner or parent/owner membership roles; viewer receives403, unrelated family/device404, missing/invalid parent authentication401. Device credentials cannot substitute for parent identity. Device is its public UUID; malformed UUID paths are404. No query parameter can change ownership, limits or date scope.

No collection, usage/location ingestion or activation endpoint is enabled. `collection_available:false` remains explicit. Tests seed future activation disclosures in isolated databases only; current sharing-v1 saved preferences never expose data. This endpoint does not provide activation or permissions and does not establish native/Firebase/browser/CI release acceptance.

## Summary contract

The response contains public device_id, revoked, collection_available, usage and location. Each feature has consent_current and retention; consent_current means an enabled, unrevoked, already-started future activation grant exists, not that collection is running. Usage includes days; location includes latest ornull. Missing/default/preference-only/future grants, revoked device or absent credential return no feature data. No raw family/child/database IDs, credential/hash, consent version, private content or event logs are returned. HTTP Cache-Control:no-store. Consumers must discard a prior summary on authorization/network failure and re-fetch rather than displaying it as current.

Usage is at most7UTCcalendar dates including today, newest first, at most100apps/day, sorted package identifiers. Only snapshot metadata matching the current consent version is considered. Untracked old totals are ignored. Snapshot time must follow max(grant,UTCdaystart), be no later than dayend/servernow, and combined positive totals fit its authorized window. Invalid/over-cap days are omitted entirely, not partially truncated into misleading totals. Valid empty snapshots show zero total and empty apps. No older data is exposed even if scheduled pruning lags.

Location returns only the latest valid-time point, not history: strictly newer than rolling24hours, at/after current grant, never future. Coordinates are rounded again to2decimal places on read to protect against older precise rows, accuracy floored1000m; out-of-range/nonfinite coordinates or invalid accuracy cause no point to be returned. This remains sensitive location, not anonymized or independently verified sensor data. Invalid latest rows fail closed rather than exposing an earlier fallback.

FamilySharingSummaryService runs its device query/consent/data reads under the same device row lock/transaction as ingestion, stop/delete and revocation, yielding a coherent saved snapshot. A read already authorized before revocation may have returned data; no server can erase a response already received by a parent. New reads after revocation return none. The GET does not mutate private data or depend on a prune command running first. A future new activation must purge old feature data as specified by the ingestion foundations.

## Verification and remaining work

Eleven new HTTP feature tests exercise owner/parent/owner-member/viewer/removed-member rules, foreign-family/device/ignored-query targeting, parent versus device bearer identity, no-store/minimal fields, preference-only denial, cutoff boundaries without pruning, current-grant/version/future filters, revoked/disabled/missing-credential failure, actual stop/revoke/family isolation, malformed legacy records and 7day/100app response bounds. Data is synthetic from existing ingestion services or isolated legacy fixtures. Authentication feature tests use actingAs to isolate authorization; this is not a live Firebase-parent browser flow.

The shared schema documents response shape; parsing it is syntax verification, not an independent runtime schema-conformance suite. Full backend suites must pass on isolated SQLite/PostgreSQL before publication. Existing PostgreSQL ingestion/revoke/stop races remain regression coverage; no new parent-response race or physical device test is claimed. Angular presentation is the next bounded slice. Native acceptance, fresh activation/Android permission flows, actual collection/background/battery acceptance, operational retention and hostedCI billing lock remain open. No development/production migration or deployment.
