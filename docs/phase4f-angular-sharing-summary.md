# Phase 4F — Angular saved sharing summary

Connected Devices offers View saved summary and Hide saved summary for one device at a time. It reads the family-authorized Phase4E contract and labels collection unavailable, preferences insufficient for collection, saved app totals by UTC date, and last saved coarse location with UTC timestamp/accuracy. No live location claim, map/third-party coordinates, parent activation control, collection request or Android permission is added.

## Privacy and response handling

The API service GET uses positive integer family/public UUID paths with the existing parent-token interceptor, ten-second timeout, and strict runtime parsing. It reconstructs only documented bounded fields; unknown payload fields are discarded. Cross-device responses, unsupported collection capability, invalid typed totals/coordinates/dates, contradictory revoked/consent data, duplicate apps/dates, totals that do not sum and over-limit arrays are rejected. Location precision beyond two decimals or reported accuracy below1000m is rejected. The shared schema remains the server contract; TypeScript does not independently prove server authorization/retention semantics. Backend filters are authoritative; browser clock is not used to make authorization decisions.

The view is created only when explicitly opened. Switching family/pages or hiding the selection destroys it and cancels HTTP. Refresh hides the previous response before requesting again. Identity observer clears saved data synchronously on signout/account change; a generation and current-input check prevents responses received before effect cleanup from repopulating an old identity/device. Subscription cleanup occurs on input changes and destruction; Firebase observer is released on destruction. Device revocation clears the open summary before the revoke request, including failure/unknown-result paths. Parent errors hide old data and display permission/session/unverified guidance. No saved summary is persisted in browser storage or a reusable service cache.

This is a saved snapshot, not a live status. Remote changes are observed on a subsequent refresh; already received responses cannot be erased remotely. Hiding on local revocation/signout does not prove another client deleted its own copy. Actual authenticated browser/tab lifecycle and accessibility inspection remain pending.

## Verification boundaries

New HTTP/parser tests cover route/method/minimized response, invalid scopes, wrong device/capability and malformed precision/types/totals/consent/date/array bounds. Component tests use synthetic RxJS subjects and Firebase identity observers to verify rendering/disclosure, request cancellation and late-response rejection, immediate signout/account-switch cleanup, refresh failures, revocation/destruction and no request without verified identity. Additional existing-component regression verifies summary selection clears before family/page changes including failed loads; auth regression verifies verified/unverified/null/error identity notifications and observer release without tokens. No real Firebase network or production/private device data is used.

TypeScript app/spec compilation, Prettier changed-file check, Angular unit suite and production build are required before publication. jsdom/unit compilation is not a real browser visual/live Firebase acceptance pass. Backend and Android unchanged: prior test results remain historical, not rerun for presentation-only changes. Native9tests and emulator acceleration/device, verified-parent browser/inbox/currentAPI and hosted CI billing lock remain outstanding. No dev/prod database/schema/settings change. Automatic development loop remains deleted; this task is a manually requested continuation.
